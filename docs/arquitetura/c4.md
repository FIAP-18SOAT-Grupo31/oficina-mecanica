# Diagramas C4

Os três primeiros níveis do C4, em Mermaid para renderizar no GitHub. Não há fila: os avisos ao cliente saem por e-mail (SMTP) depois do commit. No ambiente local quem recebe é o Mailpit.

## Legenda

| Elemento | Como aparece |
|---|---|
| Pessoa | caixa com `[pessoa]` |
| Sistema (nível 1) | caixa com `[sistema]` |
| Container (nível 2) | caixa com a tecnologia entre colchetes; o banco aparece como cilindro |
| Limite do sistema ou do container | retângulo de agrupamento (`subgraph`) com o nome |
| Componente (nível 3) | classe ou grupo de classes dentro do módulo, com a rota HTTP quando for controller |
| Fora do container | elemento com borda tracejada |
| Seta contínua | chamada síncrona ou dependência direta, com o protocolo ou a interface no rótulo |
| Seta tracejada | aviso depois do commit (e-mail) ou verificação que só bloqueia exclusão |

## Nível 1: contexto

```mermaid
flowchart TB
    atendente["Atendente / Administrador<br/>[pessoa]<br/>Cadastra clientes, veículos, serviços e peças,<br/>abre a OS, monta o orçamento e acompanha a execução"]
    cliente["Cliente da oficina<br/>[pessoa]<br/>Consulta a OS e aprova ou rejeita o orçamento<br/>com CPF/CNPJ e código de acesso"]
    sistema["Sistema da Oficina Mecânica<br/>[sistema]<br/>API REST de atendimento, orçamento e estoque"]
    smtp["Servidor de e-mail<br/>[sistema externo, SMTP]<br/>Mailpit no ambiente local"]
    style smtp stroke-dasharray: 5 5

    atendente -- "usa a API com JWT" --> sistema
    cliente -- "usa as rotas /api/publico/** sem login" --> sistema
    sistema -. "envia o e-mail (SMTP)" .-> smtp
    smtp -. "entrega o aviso com o código de acesso" .-> cliente
```

## Nível 2: containers

```mermaid
flowchart TB
    atendente["Atendente / Administrador<br/>[pessoa]"]
    cliente["Cliente da oficina<br/>[pessoa]"]

    subgraph oficina["Sistema da Oficina Mecânica (docker-compose.yml)"]
        api["API<br/>[Java 21, Spring Boot 4.1]<br/>REST + JWT, Swagger UI em /swagger-ui.html,<br/>OpenAPI em /v3/api-docs, Actuator em /actuator"]
        db[("Banco de dados<br/>[PostgreSQL 16]<br/>Esquema versionado com Flyway")]
        pgadmin["pgAdmin<br/>[dpage/pgadmin4]<br/>Ferramenta de apoio para ver o banco"]
        mailpit["Mailpit<br/>[axllent/mailpit]<br/>SMTP de teste na porta 1025,<br/>caixa de entrada em :8025"]
    end

    atendente -- "HTTP/JSON, Bearer token" --> api
    cliente -- "HTTP/JSON, CPF/CNPJ + código de acesso" --> api
    api -- "JDBC, Spring Data JPA" --> db
    pgadmin -- "SQL" --> db
    api -. "SMTP, depois do commit" .-> mailpit
```

O container `app` só sobe com `docker compose --profile app up`. Sem o perfil, sobem o banco, o pgAdmin e o Mailpit. Em produção o Mailpit seria trocado por um servidor SMTP de verdade, configurado por `MAIL_HOST`, `MAIL_PORT` e credenciais.

## Nível 3: componentes da API

Componentes da API agrupados por módulo. Cada módulo tem as camadas `domain`, `application` e `infrastructure` (ver [ADR 0001](adr/0001-monolito-modular-em-camadas.md)).

```mermaid
flowchart TB
    req["Atendente e cliente<br/>[pessoas, via HTTP/JSON]"]

    subgraph api["API [container: Java 21, Spring Boot 4.1]"]
        subgraph compartilhado["compartilhado (utilitários técnicos)"]
            filtro["LimiteRequisicoesFilter"]
            email["EnviadorEmailSmtp<br/>(ou EnviadorEmailLog com SMTP desligado)"]
            erros["TratadorGlobalDeExcecoes / ErroResposta"]
            eventos["PublicadorEventos"]
        end

        subgraph autenticacao["autenticacao"]
            seg["SegurancaConfig<br/>valida JWT e papéis"]
            login["AutenticacaoController<br/>POST /api/auth/login"]
        end

        subgraph ordemservico["ordemservico"]
            osctl["OrdemServicoController<br/>/api/ordens-servico"]
            orcctl["OrcamentoController<br/>/api/orcamentos"]
            pubctl["OrdemServicoPublicoController e<br/>OrcamentoPublicoController<br/>/api/publico/**"]
            oscasos["Casos de uso de OS e orçamento"]
            notif["NotificadorOrdemServicoAdapter e<br/>NotificadorEmailAdapter<br/>montam o e-mail"]
        end

        subgraph cliente["cliente"]
            clictl["ClienteController<br/>/api/clientes"]
        end

        subgraph veiculo["veiculo"]
            veictl["VeiculoController<br/>/api/veiculos"]
        end

        subgraph estoque["estoque"]
            estctl["EstoqueController<br/>/api/estoque"]
            estrepo["ProdutoEstoqueRepository"]
        end

        subgraph servico["servico"]
            servctl["ServicoController<br/>/api/servicos"]
            servrepo["ServicoRepository"]
        end
    end

    db[("Banco de dados<br/>[container PostgreSQL 16, fora da API]")]
    style db stroke-dasharray: 5 5
    smtp["Servidor de e-mail<br/>[Mailpit no ambiente local, fora da API]"]
    style smtp stroke-dasharray: 5 5

    req --> filtro --> seg
    seg --> login & osctl & orcctl & pubctl & clictl & veictl & estctl & servctl
    osctl & orcctl & pubctl --> oscasos
    oscasos -- "VerificadorCliente, ConsultorClientes" --> cliente
    oscasos -- "VerificadorVeiculo, ConsultorVeiculos" --> veiculo
    oscasos -- "reserva, baixa e devolução de peças" --> estrepo
    oscasos -- "lê o catálogo" --> servrepo
    oscasos -- "eventos de domínio" --> eventos
    eventos -. "depois do commit" .-> notif
    notif --> email
    email -- "SMTP" --> smtp
    cliente -- "não exclui cliente com veículos" --> veiculo
    veiculo -- "confere o dono do veículo" --> cliente
    veiculo -. "não exclui veículo com OS" .-> ordemservico
    servico -. "não exclui serviço usado em orçamento" .-> db
    autenticacao & ordemservico & cliente & veiculo & estoque & servico -- "JDBC, Spring Data JPA" --> db
```

Os erros de todos os controllers passam pelo `TratadorGlobalDeExcecoes`, que devolve `ErroResposta`.
